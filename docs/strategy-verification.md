# Strategy Verification

Runs are durable SQLite jobs (`QUEUED → RUNNING → COMPLETED/FAILED/CANCELLED`) processed by a local single-concurrency worker so market-data writes retain priority. Each run stores strategy hash, registry/engine/metrics versions, selected range, seed, options and a logical data fingerprint. Historic reports are not recalculated when candle data or strategy drafts later change.

Before queueing, availability checks every required timeframe, gap count and completeness; incomplete data blocks a run. Results persist trades, equity curve, core metrics, calendar breakdown, out-of-sample split, reproducible Monte Carlo reordering, funnel, warnings, scorecard and structured logs.

Funding defaults to `NONE`; reports explicitly warn in that case. The scorecard is a decision aid, not investment advice. Cancellation is cooperative: the simulator yields at bounded checkpoints, observes the persisted cancel flag, records partial progress and marks the job `CANCELLED` without treating it as a completed report.
# Strategy Verification report

Completed reports display the persisted closed-balance equity curve and drawdown percentage curve using compact interactive charts. These series are generated by the simulation and result store; they do not fetch or transmit the full candle history. Drawdown is explicitly the closed-balance peak-to-trough convention documented in `verification-metrics.md`.

`GET /api/verification-runs/compare` compares two completed runs without combining them. It returns side-by-side scalar metrics, persisted equity curves and breakdowns, configuration differences, and overlap based on side plus entry/exit timestamps. The dashboard warns whenever configuration hash, symbol, or requested period differs.
